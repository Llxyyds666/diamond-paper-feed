# Bark Custom Icon Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Create and self-host one original diamond-device PNG, then include its public URL in both Bark notification JSON bodies.

**Architecture:** The repository owns a static 512 × 512 PNG served by the existing GitHub Pages root. `diamond_feed.bark` exposes one non-secret icon URL constant and adds it to each outbound JSON payload while retaining the fixed official endpoint and all existing failure/security behavior.

**Tech Stack:** Python 3.11, pytest, built-in image generation, ImageMagick 7, GitHub Pages, Bark JSON API.

## Global Constraints

- Store the original asset at `assets/diamond-bark-icon.png` and publish it as `https://llxyyds666.github.io/diamond-paper-feed/assets/diamond-bark-icon.png`.
- The final PNG must be exactly 512 × 512 pixels, with a deep-blue background, cyan faceted diamond, restrained circuit traces, and no text, watermark, or third-party logo.
- Both Bark messages use the same icon.
- Keep `POST https://api.day.app/push`; put `icon` and `device_key` in the JSON body, never in the request URL.
- Preserve one attempt per message, redirect rejection, strict response validation, sanitized diagnostics, and nonfatal delivery.
- The icon is decorative and never changes message success semantics.
- Do not fetch the icon during notification delivery or CI; Bark/iOS retrieves the public asset.
- Document that custom icons require iOS 15 or later.
