# NCD/UNCD 全量 Bark 追踪

用户要求：今后所有 NCD 论文由 DeepSeek 筛选并通过 Bark 推送。

独立于综合日报和三个器件方向，复用完整采集状态与现有摘要补全服务。每六小时检查新增题录，对 NCD/UNCD 的高召回候选发送完整原始摘要给 DeepSeek。确认以纳米晶/超纳米晶金刚石薄膜、材料、生长、性质或应用为研究对象的论文全部入选；包括实验、计算、综述和预印本，不以研究方向或质量排名设门槛。排除仅使用纳米金刚石颗粒、仅背景提及、同名缩写、数据附件和封面目录。

NCD 队列不受综合日报每天 100 篇候选上限约束，不设每日模型请求数上限。每批不超过现有 batch_size，沿用网络与 JSON 故障重试。失败题录下轮重新处理，完成的批次立即检查点保存；所有请求尝试和返回的 token 单独记录。

首次部署以当时完整题录建立历史基线，避免历史论文集中推送。以后新采集的论文即使出版期号在未来也参与判断，通知将其日期标为题录日期。判断失败的记录不进入已处理集合；已排除但标题/摘要后续补全的候选重新判断。按 DOI/arXiv 与规范化同题同年身份去重，模型已确认入选的记录不重复请求。

每篇一条 Bark：英文标题、期刊、题录日期、中文摘要、NCD 入选依据和 DOI，点击进入 DOI 或论文链接。使用已有官方 Bark、图标和 BARK_TOKEN Secret。筛选步骤只接收 DeepSeek 与摘要服务 Secret，发送步骤才接收 Bark Secret。

独立 ncd_watch.json 保存历史基线、判断、待发送消息、服务接受回执与费用；不保存密钥。先将待发送消息提交到 GitHub，再发送；每条成功后保存回执，失败保持待发送。工作流最后提交回执，下一轮只重试未被接受的消息。网络超时或进程在发送成功而回执持久化前退出仍可能产生一次重复，采用至少一次投递语义。

新工作流与现有采集/日报共用并发锁，防止相互覆盖状态。手动测试允许选择一个历史 DOI，通知标注测试，不改变历史基线或正常判断。

验证：高召回边界、完整摘要、严格模型响应、超过 100 篇仍全部筛选、历史基线、身份/内容更新、跨轮失败重试、逐篇 Bark 回执和 Secret 隔离；全项目回归通过后部署并执行一次指定历史论文的模型与 Bark 测试。
